# 企业差旅智能体 Skill 开发说明

本目录包含差旅助手的业务能力插件。每个 Skill 由一份能力说明和一个独立实现组成，核心编排层通过元数据发现并按需加载，不直接依赖具体业务类。

## Skill 一览

| Skill | 职责 | 主要输入 | 主要输出 |
|---|---|---|---|
| `event-collection` | 提取行程要素 | 用户请求、已有上下文 | 城市、日期、时长、目的 |
| `memory-query` | 查询用户记忆 | 用户问题、用户标识 | 历史行程、偏好、摘要 |
| `preference` | 更新用户偏好 | 偏好描述、用户标识 | 追加或覆盖后的偏好 |
| `ask-question` | 查询企业知识 | 政策问题 | 答案、证据片段、来源 |
| `query-info` | 查询时效信息 | 天气或网络问题 | 摘要与来源 |
| `plan-trip` | 生成行程方案 | 已收集的事实与约束 | 结构化行程与注意事项 |

## 目录约定

```text
skill-name/
├── SKILL.md                # 使用场景、输入输出和约束
├── script/
│   └── agent.py            # Skill 实现
└── data/                   # 可选，只存放可公开的静态语料
```

生成的向量库、用户记忆、密钥和本地模型不属于 Skill 源码，不应提交到仓库。

## 运行约定

1. Skill 构造函数接收已经创建的模型实例，不在模块内部重复创建客户端。
2. 对外调用使用异步接口，避免阻塞编排器事件循环。
3. 返回值使用可序列化结构，至少包含执行状态；失败时返回可定位的中文错误信息。
4. Skill 只访问完成自身职责所需的上下文，不隐式修改其他 Skill 的状态。
5. 外部服务调用必须设置超时，是否重试由公共可靠性组件统一决定。

## 新增 Skill

新增能力时保持最小闭环：

1. 新建独立目录和 `SKILL.md`，明确何时调用、需要什么输入、返回什么结果；
2. 在 `script/agent.py` 中实现单一职责的 Agent；
3. 为正常结果、缺少输入和外部服务失败分别添加测试；
4. 确认 `LazyAgentRegistry` 能从元数据发现并加载该 Skill；
5. 只有当新能力确实需要时，才增加第三方依赖或公共抽象。

## 设计原则

- 业务规则放在对应 Skill，编排层只负责路由、上下文和结果聚合；
- 结构化数据优先于自然语言拼接，便于测试和后续消费；
- 对“没有知识”和“执行失败”进行区分，避免把系统错误包装成正常回答；
- 先保证一个 Skill 可独立验证，再接入完整流程。
